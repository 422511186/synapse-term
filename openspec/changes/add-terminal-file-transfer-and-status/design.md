## Context

功能动机和范围见 [proposal.md](./proposal.md)，行为契约见 [specs/](./specs/)。实现以 Electron Main 持有的本地 PTY 为基础：

- `TerminalBackend` 提供字符串输入输出，不持有 SSH client 或 SFTP channel；跨跳认证由用户在终端内完成。
- `SessionActor` 串行处理输出、输入、resize 和退出，已有普通 UI、协议控制与 Sharing 文本路径。
- 本地按键会失效当前 PTY 环境与执行上下文，`writeProbe` 不会轮换上下文；`ShellProbe.run` 可复用已验证环境。新本地写入必须显式接入失效机制。
- 外部执行已有执行上下文校验、审批、租约和事务终态；审批等待与实际 PTY 占用需要分别表达。
- 当前环境验证区分 Shell 方言及粗粒度平台，资源采集还需要实际 OS、身份和目录事实。

架构遵循 ADR-0001/0002/0004/0013 的所有权与生命周期，ADR-0015/0018/0019 的用户控制和外部执行语义，以及 ADR-0016/0017/0020 的输出与包依赖边界。

## Goals / Non-Goals

**Goals:**

- 在 SessionActor 的一个有序入口统一执行资格、上下文失效和协议输出分类，防止两个 runtime 各自维护相互矛盾的锁。
- 将本机文件授权、平台命令与协议实现封装在有限接口内，使用真实 PTY 与文件系统验证边界。
- 将可确认的文件结果、操作终态与输出通道可用性分别建模，使文件已经成功但后续输出失同步的情况能够准确表达。

**Non-Goals:**

- 通用远端执行代理、SSH/SFTP 认证复用服务、后台常驻组件或拓扑恢复。
- 整批目录原子提交、断点续传、完整文件权限/备份语义及远端目录浏览器。
- 将第三方审计产品认证、持续监控或自动环境探测加入交付范围。

## Decisions

### 1. 本地操作通过当前 PTY 的单用途前台组件执行

每次操作使用独立实例与随机响应标记。固定明文命令启动有限功能，响应包含本次标记、操作类型、实际环境、身份与目录；应用验证后才开放文件数据流。标记用于防止串线与重放，不是密码学主机身份。请求中展示的目标与响应不一致时终止本次准备，要求重新启用，不将旧路径自动转交新环境。

文件协议采用文本安全的数据帧，避免字符串 PTY 接口破坏二进制内容。组件只接受文件传输或固定采集操作，不暴露 `exec`、任意脚本、动态模块或通用命令 RPC。每次操作完成即退出前台组件。

独立 SFTP 需要额外可达性与认证；SSH ControlMaster 依赖可访问的控制 socket，不能覆盖在中间机器继续发起的跳转。因此二者不能作为通用实现基础。直接采用 xterm 文件 addon 会把文件能力放到 Renderer 并可能隐式发送 Ctrl+C，也不适用。

### 2. 文件协议适配与部署模板必须通过固定验证门槛

本地操作协调器依赖受限的文件协议适配器，不直接依赖上游 UI addon。首个候选是固定版本 `trzsz` 的文本传输模式；适配器必须提供实例握手、有限帧、逐文件完整性、受限取消和安全接收。上游实现不能满足路径或终态要求时，在同一单用途组件范围内适配文件层，不把安全要求交给上游默认行为。

通过验证后才锁定生产组件和安装资源。验证程序必须证明：三平台离线明文提供、两个方向的工具检查、多跳往返、无覆盖发布、链接竞态防护及失同步处理。未通过的实现不得进入可发布路径；验证失败不自动降低平台范围或增加联网、提权和凭证要求。协议适配器及平台部署入口保持固定，验证确定内部依赖版本、模板和平台最低条件。

组件来源、许可、摘要和完整引导随应用资源交付。已有兼容工具可直接使用；缺失时由固定明文引导在普通用户目录准备，不通过编码可执行载荷解码运行。联网包管理器是额外的显式选择，其生命周期脚本也必须检查。复制入口只提供与执行入口相同的已验证模板。

相比仅检查包管理器最外层命令，检查完整引导和真实安装行为能够验证实际执行边界；第三方日志覆盖独立于产品执行行为，不参与通用交付门槛。

### 3. 准备状态与一次性写入资格分开

面板打开和拖入仅生成准备状态。首次启用由用户确认已经回到空闲 Shell，按序执行工具检测与一次快照；工具缺失不阻断独立快照。之后每个检测、安装、上传、下载或刷新动作都需要当前用户请求和新的匹配响应。

启用记录、工具检测结果和选择摘要是运行期展示数据，不授予后台写入权。正常流程结束仅撤销该实例；用户输入、外部写入或不能确认当前环境时还使准备信息过期。组件文件可以复用，实例和执行资格不能复用。此区分避免检测结束立即把检测结果变成无用状态，也避免把“可用”当作持续执行授权。

安装方案由 Main 保存，引用绑定 Session、当前准备前提和固定参数。预览、原生选择器或冲突处理等待后，在实际写入前重新验证。安装后仅在同一有界流程取得返回同一 Shell 的证据时自动复检；成功后回到准备页面，由用户另行启动传输。

相比根据提示符、计时器或 `pty: running` 猜测空闲，主动请求能够表达用户意图；它不证明远程身份，所以仍需要本次响应和有序校验。

### 4. SessionActor 同时管理操作资格与 MCP 前提失效

在 SessionActor 内增加有序操作槽，区分本地操作、外部 Probe 和外部事务。文件选择与审批等待不长期占用该槽；外部审批仍可保留用于去重的外部调用状态，但只有再次通过上下文和操作槽校验才能写入。两个 runtime 通过 terminal-service 公共接口访问，不相互依赖。

| 事件                             | 操作资格与上下文处理                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 准备、预览或写入前取消           | 不写入 PTY，不改变 MCP 执行前提                                                                                      |
| 本地首次写入尝试                 | 同一队列内校验、取得操作槽、轮换 executionContextId、失效 CurrentPtyEnvironment 并递增 capabilityEpoch，然后尝试写入 |
| 本地操作中的合法协议块           | 只校验本次实例，不逐块轮换上下文                                                                                     |
| 操作成功、失败、取消或未确认终态 | 再次轮换 executionContextId、失效环境并推进 epoch，撤销实例后释放操作槽                                              |
| 写入抛错或交付不确定             | 进入未确认终态，保持失效，不签发可复用资格或重试                                                                     |
| 本地用户输入                     | 先撤销后续协议写入，再交付输入，保留已有完成证据                                                                     |

开始时轮换使操作前的 C0 失效，终态时轮换使操作期间 observe 得到的 C1 失效。释放占用不恢复旧上下文；本地快照和工具检测不会调用 MCP 环境验证入口。正常操作结束后，外部客户端重新 observe，并由外部执行管线验证环境。

仅设置 busy 标记无法覆盖“本地操作结束后旧审批才通过”的交错；把所有本地操作复用为自由输入又会在每块数据时撤销自身资格，因此需要独立实例保护。

### 5. 协议完整性与普通输出可用性分别收敛

协议分类位于 SessionActor 输出入口，在普通文本转换、Probe 清理、脱敏和 IPC 分片之前。分类器保存有限的跨回调帧状态，只向绑定实例交付载荷；普通文本走 UI 与 Sharing 各自的受控路径。操作未准备时，类似标记不能取得文件权限。

输出状态独立于文件结果，分为可用、等待协议终结和不可用：

| 状态         | 普通输出与恢复条件                                                                               |
| ------------ | ------------------------------------------------------------------------------------------------ |
| 可用         | 正常分类并广播普通文本，Sharing 观察可继续                                                       |
| 等待协议终结 | 停止新增数据，按有限预算处理已识别残留；只有实例结束证据、帧边界和剩余数据归属均可确认才回到可用 |
| 不可用       | 丢弃不明数据并停止普通广播、Sharing 历史追加及全部自动写入；不缓存到未来回放                     |

半帧失去可证明的边界、残留超限或终结等待超时会进入不可用。该状态在同一 Session 内不自动恢复，迟到标记、静默时间、提示符、窗口重开和重新 Sharing 都不能清除它。UI 展示原因，保留直接本地输入与关闭入口；用户可自行新建 Session，应用不自动重连、清理远端或重放认证。

这是对协议失同步采用的保守失败策略：恢复正常操作需要确定输出来源，静默超时无法提供该证据。相比无限缓存或把残片退回文本，显式停止输出能够保持有界资源和文件保密性。代价是严重协议错误可能要求用户重建 Session。

MCP 在输出不可用时先执行 Sharing 身份检查，再对 observe 和外部自动化返回 `SESSION_OUTPUT_UNAVAILABLE`，不提供新的执行上下文。status 仍只读，返回环境失效的 `not_ready` 与本地恢复指引。该错误不使用 `historyTruncated` 表达，因为历史保留窗口与协议失同步含义不同。

### 6. 文件系统访问基于有限引用和逐文件提交

Main 的原生选择器或可信拖入产生不透明选择引用；session-runtime 通过注入的文件能力访问对应根目录或文件句柄。引用绑定 Session、操作和生命周期，不接受 Renderer 任意本机路径。目录枚举不跟随链接，文件打开和创建过程必须防止路径检查后被替换。

传输相对结构在两端校验，接收端按自己的文件系统验证每级名称。Windows 拒绝 ADS、设备名称和设备命名空间；尾随点/空格及大小写、Unicode 规范化碰撞进入明确错误或冲突处理，不静默修正。合法 Shell 元字符使用平台字面引用，控制字符路径在发送前拒绝。

接收先创建本次操作专属临时文件，完整性验证后采用目的平台的原子无覆盖发布。已有文件及并发出现的同名项保持不变；跳过或换名决定绑定冲突项与操作实例，换名后重新验证。等待冲突选择使用有限预算，窗口分离不授权自动覆盖。批次只承诺逐文件提交，成功文件保持，临时文件仅在能确认归属时清理。

相比存在性检查后直接打开最终文件，这种方式避免中途断开留下被误认为成功的目标，也避免同名竞态覆盖用户数据。不能用字符串前缀检查代替句柄级目录约束。

### 7. 资源预算覆盖数据和目录元数据

协议适配器须在启用前提供一组固定预算，禁止无限帧、无限解压和无限目录结果。初始验证使用下列工程预算；调整必须保持规格中的有界与显式超限语义，并将通过压力验证的值固定在实现中。

| 项目                             | 初始预算                                           |
| -------------------------------- | -------------------------------------------------- |
| 单帧编码内容 / 解压后内容        | 128 KiB / 512 KiB                                  |
| 未确认发送窗口                   | 1 MiB                                              |
| 单操作 / 应用内本地操作缓冲      | 16 MiB / 128 MiB，达到应用预算时拒绝新操作         |
| 目录枚举                         | 最多 10,000 项、128 层，同时受元数据内存预算约束   |
| 状态分页与事件                   | 每页最多 200 项且不超过 32 KiB，进度最多每秒 10 次 |
| 握手 / 无进展传输 / 取消终结等待 | 30 秒 / 60 秒 / 5 秒                               |
| 单次快照 / 安装流程              | 10 秒 / 10 分钟，超时按实际证据收敛                |

读取、解压、写盘和发送均实施背压；不把整个文件载入内存。超时不自动重试。接管后停止发送的保证从撤销资格开始，此前已进入 PTY/SSH 缓冲的数据无法撤回。

### 8. 快照使用独立采集契约

平台采集器验证实际 OS 与 Shell 方言，执行一个有开始/结束标记的固定明文片段，在同一执行范围内输出结构化结果。Linux 使用平台计数器与文件系统数据，macOS 使用原生统计工具，Windows 使用未编码 PowerShell/CIM；PowerShell 方言本身不代表 Windows。

CPU 差分在同一操作中采样；容器优先采用可验证 cgroup 限额与使用量，无法确认时显示系统可见口径或不可用。磁盘指向本次目录所在文件系统。混杂环境、结束证据丢失或超时不发布成功快照；独立指标缺失只影响该项。

快照包含 capturedAt、环境事实、值、单位、统计范围、采样区间和不可用原因，与 CurrentPtyEnvironment 分离。成功采集正常收敛时失效 MCP 执行前提，但该失效事件不使刚完成的样本立即过期；其他输入或环境变化仍使样本过期。使用普通系统命令减少组件依赖；使用一次有界采集片段避免多条独立命令跨环境拼接。

### 9. 包接口与生命周期

| 所在层             | 职责                                                             |
| ------------------ | ---------------------------------------------------------------- |
| domain             | 本地操作、工具检测、文件结果、快照与输出可用性的纯数据契约       |
| terminal-service   | Session 顺序、操作槽、上下文失效、协议分类、接管与不可用状态     |
| session-runtime    | 本地流程、文件协议适配器、文件能力调用与平台采集                 |
| Desktop Main       | 组合根、打包资源、原生选择、固定安装方案、IPC 来源及参数校验     |
| preload / Renderer | 有限操作请求、选择或方案引用、结果与恢复提示                     |
| mcp-runtime        | 使用公共操作资格和普通输出，映射忙碌、上下文冲突及输出不可用错误 |

桌面接口涵盖准备/启用、检测、安装方案预览/执行、选择、传输、冲突处理、取消、快照刷新和有界状态分页/订阅。任何异步回调都绑定 Session 与实例；Renderer 不获得可重放的内部资格、文件流或原始协议。

窗口分离后 Main 继续运行已启动操作，重开仅返回当前状态。Session 关闭、退出和已确认更新清理会释放操作、引用、文件流与 PTY。Sharing 撤销和 Token 吊销只清理外部调用，不影响本地操作或重置输出状态。所有运行状态不跨应用重启保存。

## Risks / Trade-offs

- [离线明文组件提供依赖目标基础工具] → 三平台分别验证并声明最低条件；不以预装工具、联网或提权替代离线基线。
- [候选协议缺少无覆盖发布或链接防护] → 通过受限适配器完成文件层约束，未通过真实文件系统验证前不开放入口。
- [SSH 回退时仍有已排队输入] → 限制未确认窗口，观测失效后立即撤销资格，交付无法确认的部分按未确认处理。
- [协议失同步导致终端输出暂停] → 使用显式不可用状态保留用户控制，不以静默超时恢复，说明重建 Session 的操作代价。
- [取消造成远端临时文件残留] → 只清理可确认归属的资源，失效后不发送删除命令，逐项报告已知残留。
- [三平台指标含义不同] → 单位、采样区间与统计范围随结果提供，缺失值不填零。
- [第三方审计未记录工具内部文件动作] → 通用交付验证实际明文执行行为，特定产品日志覆盖仅作为可选兼容性说明。

## Migration Plan

1. 使用独立验证程序确定适配器、部署模板和预算的可行实现，记录脱敏的版本、命令与结果至本 change 的 `validation.md`。
2. 先完成 Session 有序协调、上下文失效和协议输出隔离，再交付单文件往返；随后扩展目录、检测安装、快照和桌面流程。
3. 在实施变更中更新 CONTEXT.md 的稳定术语，为选定协议、输出失败策略和接口取舍记录 ADR，并同步架构、安全、操作和测试说明。
4. 完成三平台、多跳、竞态、异常与生命周期验证后开放功能。回退时移除入口并终止在途本地操作，保留用户保存文件，不跨失效环境删除组件或恢复任务。
