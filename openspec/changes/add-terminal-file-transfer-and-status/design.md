## Context

本变更基于 [proposal.md](./proposal.md) 中已确认的产品范围。用户允许新环境主动启用一次、文件传输占用当前终端和按需状态快照；目标平台同时包含 Linux、macOS、Windows。命令和脚本不得加密或 Base64 编码，文件内容作为协议数据可以编码。

当前实现有四个直接影响设计的事实：

- `TerminalBackend` 只有字符串输入输出，应用不持有 SSH client、SFTP channel 或各跳认证信息。
- `SessionActor` 串行处理输入输出，现有能力代际和执行上下文 ID 只防止已知前提过期；`pty: running` 不证明空闲 Shell，也不证明最内层机器身份。
- 当前环境 Probe 主要验证 Shell 方言，其 `unix/windows` 结果不足以区分真实 Linux、macOS 或跨平台 PowerShell，不能直接作为指标采集器的选择依据。
- Session 输出已有普通终端、协议控制和 Sharing 文本的不同消费者；文件内容不能经过文本清理、脱敏或截断路径。

ADR-0001/0002/0013 规定 Main 所有权、传输无关和本地单用户边界；ADR-0015/0018/0019 要求用户控制权和写入不确定语义；ADR-0016/0017 规定协议与输出边界；ADR-0020 规定 runtime package 的依赖方向。

`desktop-terminal` 当前禁止 Header 资源监控，因此本变更将快照放到 Session 内容区。Sharing 主规格的一处“五个工具”旧文案与 ADR-0019 和当前八工具实现不一致；本变更不改变工具数量，只修改输出隔离要求，不据此恢复已移除的文件工具。

## Goals / Non-Goals

**Goals:**

- 在已登录的当前终端通道上传、下载多文件与目录，认证始终由用户已经建立的链路提供。
- 对操作时实际响应的最内层环境和身份执行有限文件操作与状态采集，跨跳转时保守失效。
- 提供三平台的环境、用户、目录、CPU、内存、磁盘快照及明确的时间、口径和不可用状态。
- 让全部检测、安装、启动、采集和文件操作命令以可检查原文到达目标，提供目标侧审计验收证据。
- 补齐手动/受控自动检测、缺失提示、快速安装和安装后复检，使用户能从准备操作走到工具可用，并分清不可用与结果未确认。
- 保持 Renderer 隔离、Session 并发顺序、本地接管、Sharing 脱敏与应用生命周期。

**Non-Goals:**

- 新建 SSH/SFTP 认证、自动重放凭证、SSH agent 代理、端口转发、远端服务端点或连接拓扑恢复。
- 远端目录浏览器、在线编辑、网络速率、进程列表、持续监控、繁忙终端中的并行传输。
- MCP 文件/快照工具、主机资产、集中审计日志、后台常驻远端代理或跨应用重启恢复任务。
- 通过本地窗口展示或隐藏内容来替代目标侧审计；承诺所有堡垒机、Shell、容器和审计产品都兼容。

## Decisions

### 1. 使用当前 PTY 通道，以有限操作为单位取得控制

每次上传、下载、启用、工具检测/安装或采集都有独立的操作实例和不可重放的随机标记。通过当前 Shell 明文启动一个单用途操作后，收到本次匹配的响应才进入文件数据阶段。文件接收器在确认前不创建最终目标文件。

```text
Renderer -> restricted preload -> Desktop Main
                                   |
                         session-runtime
                                   |
                         SessionActor queue
                                   |
                       existing local PTY
                                   |
                existing SSH / bastion / container chain
                                   |
                   current foreground operation
```

复用的是既有终端通道，不是从 PTY 中提取 SSH 连接。ControlMaster 依赖已有且可访问的控制 socket，也不能从本机直接复用中间主机自行发起的后续 SSH；新建 SFTP 需要额外可达性和认证前提。因此不采用这两种方式作为本变更的基础。

环境名称、用户和目录是响应中的显示事实，不构成密码学主机证明或持久身份。操作实例只证明本次协议响应的一致性，不能把任何旧握手解释为今后的执行授权。

### 2. 明文命令与文件数据有不同的职责

Main 从固定操作类型、平台命令模板和已校验的路径生成明文命令。文件路径作为参数处理，拒绝不能明确引用的控制字符；不将 Renderer 提供的字符串当作任意命令执行。

每次文件操作使用明确的上传或下载启动命令，状态采集使用固定明文命令或完整可检查的固定采集片段。辅助组件只允许特定文件/采集功能，不提供 `exec`、任意脚本、动态模块或通用 `--stdio` 执行入口。文件协议中的编码内容只可成为指定文件的数据，不能成为待执行命令、脚本或插件。

禁止命令加密、Base64/等价编码脚本、解码后执行、`eval`、`EncodedCommand` 和通过可执行文件上传再自动执行来隐藏引导。普通 Shell 参数引用及文件数据编码不受此禁令误伤，SSH 的既有传输加密保持不变。上传用户文件不会自动启动该文件。

不能仅检查发出的字符串不含 `base64`：编码命令可能已经由调用方生成，也可能藏在辅助程序的协议中。校验需以操作类型、可信模板、完整引导源码和辅助程序不具备任意执行入口为依据。现有 MCP 字面命令语义保持不变。

### 3. 首次部署与协议选型先通过验证

`trzsz` 是首选调查对象，尚未选定生产依赖。已核查其 JS 实现：普通数据使用压缩与 Base64；文件名和配置也会编码；默认拖入流程发送 Ctrl+C 后启动 `trz`。因此需要单独适配操作启动、取消、协议隔离和审计信息，不能直接安装 xterm addon 后宣称完成。

**检测对象与结果**

候选 `trzsz` 在目标端以 `trz` 接收上传、以 `tsz` 发送下载，因此必须分别检测两个工具。检测通过当前 PTY 使用固定、无变更意图的明文命令，报告实际可执行路径、版本和本项目要求的协议/目录传输等能力；仅发现同名命令不能判定可用。若最终更换组件，适配器仍须分别报告上传与下载能力，不能省略同等检查。

POSIX 的 `command -v trz` / `command -v tsz`、PowerShell 的 `Get-Command trz,tsz -CommandType Application -ErrorAction SilentlyContinue` 可作为定位步骤示例，随后对解析出的可执行路径进行受限版本/能力检查。具体模板须经过三平台验证；不能仅凭 PATH 文本、别名、函数或安装命令退出码判断结果。

每个方向分别展示以下状态；结果只在当前应用运行期保留，附检测时的环境与时间，不构成执行授权：

| 状态 | 判定与后续动作 |
| --- | --- |
| 未检测 / 检测中 | 尚无结论或正在进行一次有界检查，不能显示可用 |
| 可用 | 已确认所需工具路径、兼容版本和运行能力；仍须取得本次传输响应 |
| 缺失 | 检测完整结束且确认工具未找到，提示适用安装方式 |
| 版本或能力不兼容 | 找到工具但不满足本项目协议要求，说明具体差异，不静默升级 |
| 执行受限 | 已确认权限、执行策略或可执行位置阻止运行，说明限制，不自动绕过 |
| 检测未完成 | 超时、取消、输出不可解析或无可靠结束证据；不能据此判为缺失或自动安装 |
| 过期 / 待复检 | 当前操作前提失效，旧结果仅供参考，需要重新建立前提并检测 |

**安装路径**

1. 已有兼容且允许运行的工具直接使用，不重新安装；上传与下载分别依据其实际所需能力决定可用性，一侧缺失不必禁用另一侧。
2. 基线仍是应用提供固定版本组件及完整可检查的明文引导，经当前 PTY 在用户允许的可写/可执行位置准备；不依赖目标联网、提权或新凭证，不修改 Shell 启动文件、不创建后台服务。必须证明基础工具能够完成引导，且实际执行内容在目标审计中具备所需可见性。
3. 经验证、目标认可且满足当前用户权限的联网包管理器安装可作为可选方式。界面须标明联网、来源、固定版本、安装位置及基础工具要求，由用户明确选择后执行；不能静默联网或替代第二条的离线验收。不能仅因包管理器命令可读就宣称其安装脚本/生命周期动作符合审计，实际安装行为也须纳入验证。
4. 用户可以通过目标认可的方式手工安装，再请求重新检测。应用生成的可复制命令仍须来自相同的已验证模板；没有适用模板时只展示原因和手工安装指引，不生成未验证的“快捷命令”。

快速安装先展示完整明文命令及上述条件，再由用户选择在当前终端执行或仅复制。Main 持有固定安装方案，Renderer 只提交方案引用；选择/确认后重新校验 Session、环境与操作资格，不能把旧安装命令发到刚跳转的新环境。安装不是 MCP 审批，也不授予外部客户端能力。

安装后必须重新检查实际路径、版本和运行能力。工具已装到用户目录但不在 PATH 时，可显示并验证本次安装的明确绝对路径；不自动编辑 Shell 配置或要求重新登录。复检成功后返回原上传/下载准备页面，保留可供复核的选择摘要，不自动开始传输或恢复失效文件授权。缺少安装结束证据、用户接管或环境变化时暂停复检，显示未确认/待验证，不自动重跑安装；失败时保留具体原因、手工安装指引和重新检测入口。

第二条的离线首次部署尚未验证。不得将预编译组件或编码脚本包装成“文件数据”后自动执行来规避验证；快速安装也不能使用下载即执行的不透明脚本、编码引导或执行策略绕过。没有符合审计的安装路径时，快捷执行不可用并说明原因，普通终端及独立满足前提的快照采集仍可使用。

首批验证需要交付：

| 验证项 | 必须形成的证据 | 不通过时的处理 |
| --- | --- | --- |
| 三平台首次部署 | 固定组件来源/版本/许可/摘要、完整明文命令、基础工具与权限要求、离线普通用户部署记录 | 不进入组件自动部署的生产实现，不以预装前提冒充已满足自动提供组件 |
| 检测与安装复检 | 三平台两个方向的路径/版本/能力检查，缺失、不兼容、执行受限、超时、PATH 未更新及环境变化记录；适用的安装完整命令和复检结果 | 无完成证据不判缺失，安装退出码不替代工具可用性，不自动补装或重试 |
| 目标审计 | 审计产品与记录方式、检测/安装/复检/启动/采集/取消命令及安装内部动作的预期和实际记录、是否要求逐文件路径 | 不宣称该审计环境受支持；不能用本地日志或协议摘要替代 |
| 多跳文件协议 | 双跳 SSH、Linux 容器/WSL、tmux 和目标审计链路中的上传下载、终止与完整性 | 对具体不兼容链路返回不可用，不回退新认证或隐藏命令 |
| 单实例绑定 | 回退上一层、接收器退出、迟到帧和本地输入时停止继续发送的证据 | 保留未确认结果，不开启自动重试 |

三种目标平台都是首版验收范围，不能通过把整个平台标为“不可用”来完成本变更。个别不满足已声明基础条件的环境可以明确不支持。具体最低 Shell/版本/架构和组件方式由验证记录确定；若验证要求缩减平台、增加联网/提权/凭证前提，必须先修订本提案，不能作为实现细节静默处理。

### 4. 明确启用、空闲前提与目标失效

初次打开文件/快照面板只展示说明，不向未知 PTY 注入 Probe。用户在已经回到空闲 Shell 后执行应用提供的明文启用步骤。后续点击检测、安装、上传、下载或刷新是一次当前操作请求，不会赋予应用后台周期注入命令的权利。

手动“检测当前环境”入口在用户声明回到空闲 Shell 并满足明确启用前提后发起一次检查；前提未知时先展示启用步骤。自动检测只允许发生在用户主动选择的有界启用流程中一次，以及具有有效当前操作前提的上传/下载准备流程中按需复检。打开面板、切换 Session、普通输出、拖入文件和计时器不触发检测；已知繁忙或前台未知时不排队等待“看起来空闲”后执行。

检测、安装和复检与其他本地操作共用 SessionActor 的串行资格，与快照、MCP Probe 和外部写入互斥。首次工具检测和首次快照按序作为明确启用流程的有限步骤执行，工具缺失不阻断独立可用的快照。安装后的自动复检只能作为同一有界安装流程的后续步骤，在取得安装命令返回同一 Shell 的可靠完成证据后重新检查资格；不能将“安装命令看似结束”或旧检测结果当作空闲证明。流程终态撤销写入资格，后续传输重新建立操作实例，不从检测/安装成功继承授权。

用户输入、外部写入、操作结束、PTY 退出和协议丢失会使执行绑定失效；旧检测结果标记为过期，已选择但尚未执行的安装方案也必须重新校验。新环境需要重新启用；已准备组件可以复用文件本身，但不能复用旧操作实例。启动命令前和文件选择/路径确认等等待阶段后检查本地顺序及有效性，每次开始文件数据或发布快照前必须取得本次响应。

普通终端输出、Shell 提示符和 `pty: running` 不作为自动启动证据。用户在编辑器、密码提示或菜单中时不自动 Ctrl+C、不猜测空闲、不定时尝试启动；未知状态需要用户回到 Shell。可能已经回退上一层时，新响应与请求时展示的环境不一致就取消本次目标绑定，先重新启用；不能自动将旧路径操作转交给新响应者。

单个快照也需要有限的同一执行范围及开始/结束的一致性证据；不能将多条可能跨越环境切换的命令结果拼成成功快照。固定明文采集片段如何保持该范围，属于三平台验证的一部分。

停止发送的保证从应用观测到失效并在 Session 队列撤销资格开始生效。此前已经交给 PTY/SSH 缓冲的字节无法撤回，也不能证明目标尚未消费；这部分交付只能按实际完成证据或未确认结果处理。实现和验收不得把一次握手描述为后续绝不退回上一层的保证。

### 5. Session 级协调位于 terminal-service

在 SessionActor 的同一顺序中维护本地操作与外部写入的互斥资格。`session-runtime` 发起本地操作，`mcp-runtime` 通过下层公共接口检查资格，两个 runtime 不相互依赖。

- 文件操作或快照占用资格期间，MCP Probe、结构化执行、交互启动和自由输入不得写入 PTY；已 Sharing 的只读观察仍可返回普通脱敏文本。
- 外部事务或正在进行的外部 Probe 持有资格时，本地功能返回忙碌，不中断对方。审批等待不成为本地用户锁；审批结束后必须再次验证上下文及资格。
- 本地普通按键仍保持可用。用户接管先停止后续协议自动写入、撤销未使用资格，再按既有用户输入路径交付输入；不得缓存后在 Shell 恢复时重放这些按键。
- 取消向当前操作发送有限取消请求或本地 PTY 中断，不承诺远端进程已经结束。缺少结束证据时进入未确认结果，不继续发送清理命令或文件块。

操作状态分为准备/握手、传输或采集、取消中和终态。终态明确区分成功、已确认失败、已确认取消、部分完成及结果未确认。写入前拒绝不声称远端失败；backend `write()` 返回只代表本地接受，不能直接转为成功。

### 6. 文件路径、流式处理和结果

本机上传/下载位置由 Main 的原生选择器或真实文件拖入形成操作范围内的文件句柄；Renderer 只持有有限的选择引用和展示元数据，不能靠任意字符串读取本机文件。远端路径是显式用户输入，按目标平台引用；相对路径只依据本次响应的目录解析。

首版支持多个普通文件和目录，保留目录结构。默认不跟随符号链接、Windows reparse point 或其他特殊文件，逐项显示跳过原因；不承诺 owner、ACL、稀疏属性或备份语义。同名默认不覆盖，用户可跳过或换名，首版不提供隐式覆盖及断点续传。

传输使用有上限的分块、未确认窗口、解压后帧大小和内存预算，包含背压、超时、进度节流与内容完整性校验。实现前将具体常量写入验证记录，并覆盖超限输入；不限制为“整个文件一次载入内存”。接收时逐文件使用操作专属临时文件，验证结束后以不覆盖已有文件的方式发布；目录批次不承诺整体原子提交，结果逐项汇总。

远端提供的文件名、相对路径及目录元数据是不可信输入。下载不得通过绝对路径、`..`、分隔符混用、符号链接或 reparse point 逃出用户选择的本机目录；上传接收端也要维持其选定根目录边界。路径检查与最终创建要抵抗检查后替换，不能仅作字符串前缀比较。

取消、断线或本地接管后，只清理可以确认仍属于本操作的临时文件；不再向可能已经改变环境的 Shell 发送远端删除命令。已完成文件保留，未确认的远端临时文件位置仅作尽力报告，不声称不存在残留。

### 7. 快照是按需显示数据

快照保持独立于 `CurrentPtyEnvironment`，包含 `capturedAt`、实际 OS、当前用户、目录、环境显示名、指标值与单位、采样区间、统计口径和逐项不可用原因。快照 ID 不授权执行，也不进入 MCP `synapse_status`。

平台适配器使用固定明文命令，输出在本机解析。Linux 使用平台计数器及文件系统数据，CPU 利用率需要同一操作内两次采样；macOS 使用其原生统计工具；Windows 使用未编码的 PowerShell/CIM 等系统能力。平台和 Shell 方言分别验证，不因 PowerShell 方言就推断目标必然是 Windows。

Linux 容器优先获取可确认的 cgroup 配额和使用量。不能确认时标记为容器不可用或明确显示宿主机/系统可见口径，不能将 `/proc` 的宿主机总量作为容器限额。磁盘空间按本次目录所在文件系统展示。缺少命令、权限或字段只使相应指标不可用，不用零值代替。

启用后采集一次，随后由用户在空闲 Shell 手动刷新；不启动后台计时命令。输入或操作变化后旧快照显示采样时间与过期/待验证状态，繁忙时显示暂停。返回上一层后不能把旧环境的数据改标签后当成新数据。

### 8. 输出分流与包接口

辅助协议在 SessionActor 输出入口、普通文本转换之前分类，绑定当前活动实例，处理跨回调半帧并限制帧与解压大小。只有主动准备且与本次请求匹配的协议可消费文件选择引用；无关终端文本中的类似标记不能自动访问本机文件。解析器在截断、取消和迟到数据后也不得把文件载荷回灌普通终端或 Sharing 历史，异常时终止操作并有界处理残留协议。

普通命令回显、普通结果和用户文本继续按顺序走 UI/Sharing 路径。文件载荷、协议帧和内部结构化快照只交给指定消费者，不以“脱敏后就可公开”处理文件。目标收到的明文输入与远端审计不因 Main 的 UI 分流而改变；本机选择文件的完整路径不发送给远端。

| 所在层 | 责任与接口 |
| --- | --- |
| domain | 本地操作/文件结果/快照的纯契约，含逐项状态和不可用原因 |
| terminal-service | 有序操作资格、实例标记、协议路由、取消与失效；对 runtime 只暴露公共操作接口 |
| session-runtime | 本地操作协调器、文件流和平台采集适配；通过注入的本机文件能力使用 Main 选定文件 |
| Desktop Main | 组合根、组件资源、原生选择与有限文件授权、IPC 校验与事件广播 |
| Renderer/preload | 准备/启用、工具检测、固定安装方案预览/选择、上传/下载、取消、快照刷新及状态订阅；不接受任意命令、任意网络地址或原始 PTY 字节 |
| mcp-runtime | 使用同一 Session 写入资格，继续提供原有工具及清理文本，不消费本地文件句柄或快照 |

建议契约分为 `prepare/activate`、`detectTools`、`getInstallPlan/installTools`、`upload/download`、`cancel`、`refreshSnapshot` 和有界 `onChanged/getState`，具体命名在实现时遵循现有公共出口。安装方案来自 Main 中经过验证的模板及当前检测结果，包含版本/来源/位置/条件和完整只读命令预览，不接收 Renderer 自定义命令或下载源。所有异步回调绑定 Session 和操作实例，过期选择、迟到进度和取消后回调不得再次取得文件/PTY 写入权。

### 9. UI 和生命周期

会话菜单提供“文件传输”“环境快照”入口，内容区显示可关闭的本地面板；Header 保持现有品牌、标签、会话操作和设置布局。拖入只准备上传，不能自动中断前台程序或在未知环境发送启动命令。

文件面板提供“检测当前环境”，分别显示上传接收工具 `trz` 和下载发送工具 `tsz` 的状态、路径、版本及检测时间。缺失时提示“当前环境缺少文件传输工具”，提供适用的“快速安装”“复制安装命令”“重新检测”；不兼容、执行受限和检测未完成使用各自原因，不统一显示为未安装。不存在已验证且适用的安装方案时，快捷执行/复制入口不可用并说明原因，用户仍可手工安装后重新检测。

典型上传流程：准备文件 → 在空闲 Shell 明确启用 → 检测两个方向的工具 → 缺失时查看安装方案 → 用户选择明文执行或自行安装 → 有效前提下复检 → 回到上传准备并复核目标/文件 → 用户启动本次上传。取消安装返回准备状态；未经确认不安装，安装成功不自动发送文件。若等待期间操作或选择引用已失效，则提示重新启用/选择，不能延长旧授权。

窗口分离后已启动操作仍由 Main 维护，重开读取当前进度和快照状态；不回放终端历史，不自动重启传输。Session 关闭、应用退出及已确认应用更新的 Session 清理会撤销资格、关闭本机文件流并终止 PTY。未完成选择不创建远端操作。取消 Sharing 或吊销 MCP Token 只撤销外部调用，不取消用户本地文件操作。

只持久化用户明确选择保存的传输结果。启用记录、文件授权、操作状态、快照和目标审计记录不跨应用重启保存。应用提供的远端组件/引导临时文件采用有限清理；无法确认目标仍在原环境时不追加删除命令，不把尽力清理承诺为远端无残留。

## Risks / Trade-offs

- [审计只记录辅助程序启动，看不到实际动作] → 明确每次操作的明文启动命令，禁用任意执行协议；以目标实际记录验收。逐文件路径是否必须记录由目标审计要求确定，编码文件名不能冒充可读路径审计。
- [明文引导依赖目标基础工具或受执行策略限制] → 三平台前置验证并记录最低条件；缺失时显示不可用，不改用编码引导、不要求重复凭证。
- [检测误判或安装后仍不可执行] → 两个方向分别报告路径、版本、运行能力及完成证据；超时不判缺失，安装后复检 PATH 与明确安装位置，旧结果不授权操作。
- [快捷安装被误认为离线部署已解决或审计天然通过] → 联网方式仅为显式可选路径；安装内部行为与完整命令一并验收，离线基线与实际目标审计仍是独立未完成项。
- [终端通道被堡垒机、tmux、ConPTY 或中间程序过滤] → 使用有界帧与校验，实测关键组合；不承诺所有链路透明，不用数据丢失后的自动重传跨越新环境。
- [一次握手后通道退回上一层] → 每次操作使用新实例与完成证据，尽早停止发送；测试已排队输入和残留数据，禁止自动启动新接收器。标记不能提供密码学主机认证。
- [独占传输降低交互便利性] → 用户已接受前台占用，保留取消和即时接管；不采用上游默认 Ctrl+C 启动行为。
- [目录传输部分完成或临时文件残留] → 逐文件提交与逐项报告，默认不覆盖，不自动远端清理或继续未确认任务。
- [三平台指标含义不同] → 显示单位、采样区间和口径，能力缺失显式呈现；不把所有目标都标不可用后宣称三平台支持。

## Migration Plan

1. 完成明文部署、目标审计、多跳协议和绑定失效验证，记录结论到本 change 的验证记录；不使用真实凭据或主机标识入库。
2. 在同一变更中更新 `CONTEXT.md` 的“本地终端操作”“文件传输”“环境快照”等术语，并为通过验证后的协议/审计取舍新增下一可用编号 ADR，关联本 change；不预先把候选依赖记为已接受决策。
3. 先实现 Session 级操作资格和输出隔离，再实现单文件纵向流程；扩展目录、取消、三平台快照和 UI。所有代码行为配同层回归测试。
4. 完成真实三平台、多跳、用户接管、Sharing 以及窗口/退出/更新清理验收，再开放完整功能入口。未通过的整个平台或审计前提不能在任务清单中勾选完成。
5. 回退时移除新入口并终止在途本地操作，不修改用户 SSH 配置、Shell 启动文件或凭据；用户已保存文件保留，不尝试跨失效环境回收远端组件。

## Open Questions

以下是实施首批任务要回答的技术问题，不是尚未决定的产品范围：

- 三平台在目标不联网、普通用户权限下，可审计的组件首次部署具体依赖哪些基础工具、Shell/OS 版本及 CPU 架构？能否形成完全明文的引导而无需编码可执行内容？
- 实际审计系统记录终端输入、Shell 命令、进程参数还是脚本执行内容？是否额外要求逐文件路径与覆盖结果？尚无真实审计样本，不能填写“通过”。
- 固定版本 `trzsz` 能否满足受控启动、文件安全边界、实例绑定和取消语义，还是需要固定单用途适配组件？不得因此引入通用远端执行代理。
- 两个工具各自的最低兼容版本、能力检查命令、安装目录和 PATH 处理方式是什么？各平台可提供哪些满足目标审计的固定安装方案，包括可选包管理器安装的内部脚本行为？未验证前不生成自动执行方案。
- 同一快照的有限执行范围及结束证据，在各平台上如何以完全明文的采集片段实现？未知或混杂输出必须失败而非发布成功快照。
- 各支持组合中的分块、未确认窗口、解压上限、超时和进度节流预算是什么？由压力与异常协议验证确定后固化。
