## Why

用户在终端内完成 SSH、跳板机、容器、WSL 或身份切换后，需要直接向当前环境上传、下载文件并查看资源状态。独立文件客户端通常无法复用完整认证链路，因此应用需要沿当前 Session 的 PTY 提供这些能力，避免重复认证。

## What Changes

- 在 Session 内容区增加文件传输和环境快照面板，支持多文件、目录上传下载、拖入准备、远端路径输入、进度、取消与逐项结果；同名文件默认保留，提供跳过或换名。
- 使用当前 PTY 通道和当前身份操作 Linux、macOS、Windows 目标，每次启动验证独立操作响应；不创建 SSH/SFTP 连接、主机资产或凭据库。
- 提供用户主动启用、手动工具检测、有界流程内的自动检测、快速安装预览、复制安装命令和安装后复检。组件提供以离线、普通用户权限为基线；联网安装由用户明确选择。
- 使用固定明文命令完成检测、部署、传输启动和快照采集。文件内容可以编码传输，执行命令和脚本不得编码或隐藏在文件协议内；交付验证以实际执行行为为依据，不要求第三方审计系统通过记录。
- 快照显示当前环境、身份、目录、CPU、内存、磁盘、采样时间和统计口径；启用时采集一次，之后手动刷新，不向繁忙或未知前台定时注入命令。
- 将本地操作与 MCP 写入纳入 Session 级协调，保留本地接管能力，在本地操作写入与终态时失效 MCP 执行前提。
- 在 Main 隔离文件协议、载荷和内部快照。无法确认输出边界时显式暂停普通输出及外部访问，避免把迟到载荷当作文本；正常传输期间普通 Sharing 观察保持可用。
- 操作状态、文件授权与快照仅存在于应用运行期；窗口分离不终止已启动操作，Session 关闭或应用退出释放资源，用户保存的文件保留。

## Capabilities

### New Capabilities

- `terminal-operation-audit`：固定明文执行、主动启用、工具检测、组件提供、安装复检和通用执行验证。
- `terminal-file-transfer`：当前 PTY 上的多文件与目录传输、受限文件访问、目的文件系统名称规则、流式处理和逐项终态。
- `terminal-environment-snapshot`：三平台按需采集、指标口径、采样完整性及运行期快照展示。

### Modified Capabilities

- `terminal-sessions`：统一操作资格、MCP 上下文失效、协议隔离、失同步处理和本地操作生命周期。
- `desktop-terminal`：Session 内文件与快照入口、检测安装流程、受限 IPC 和异常反馈。
- `mcp-session-sharing`：本地协议的输出隔离、失同步错误及本地操作与 Sharing 的独立撤销语义。

## Impact

- `packages/domain` 增加本地操作、工具检测、文件结果、输出可用性和快照的纯数据契约。
- `packages/terminal-service` 承担 SessionActor 内的有序资格、执行前提失效、协议路由和接管处理；`packages/session-runtime` 承担本地操作、文件流与平台采集。
- `apps/desktop` 的 Main 管理组件资源、原生文件选择和 IPC 校验，preload 暴露有限接口，Renderer 展示操作状态。
- `packages/mcp-runtime` 使用下层公共协调接口，增加输出失同步的稳定错误；八个工具、三档审批和输出脱敏保持，外部客户端不获得文件或快照能力。
- 文件协议候选为固定版本 `trzsz`；生产依赖、适配方式与最低平台条件由专项验证确定。实施包含三平台、多跳、文件系统、并发和生命周期验证，以及领域术语、ADR、架构、安全和操作文档更新。
