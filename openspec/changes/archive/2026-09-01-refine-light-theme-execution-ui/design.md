## Context

当前 Renderer 已通过 `ThemeState` 接收有效 scheme，并由主题调色板设置 CSS 变量；但 `styles.css` 中的执行状态、审批卡片和 MCP 设置仍有大量直接写入的深色主题颜色。浅色主题只覆盖了少数选择器，导致状态文字、危险操作和浅色背景上的浅色标签对比度不足。

终端面板中的外部执行状态目前是绝对定位的条幅，命令全文直接换行，既会把条幅撑高，也会覆盖下方 Terminal Session 输出。审批卡片通过现有 preload API 接收完整请求并提交三个既有裁决动作；设置工作区也已经具备通用、外观和 MCP 服务三个区块。本变更只调整 Renderer 的布局和主题表现，不越过 Renderer/preload 边界，也不改动 Main 的审批、Session、PTY 或外部调用语义。

## Goals / Non-Goals

**Goals:**

- 为浅色和深色 scheme 建立可复用的语义颜色层，保证执行状态、审批状态和设置控件在两种主题下都能阅读和区分。
- 让外部执行状态栏占用真实布局空间，长命令不遮挡 Terminal Session 输出，同时保留命令、来源和持续时间范围的现有展示语义。
- 提升审批卡片和设置工作区的信息层级、操作清晰度、窄窗口适配和键盘焦点可见性。
- 对自定义核心配色提供对比度反馈与受影响 UI 的 scheme 安全回退，不静默修改用户保存的合法颜色值。
- 用组件测试、颜色对比度测试和浅色/深色视觉验收锁定结果。

**Non-Goals:**

- 不改变 `read_only`、`managed`、`full` 审批模式及审批队列、60 秒超时、会话内放行或错误码。
- 不改变 Sharing、Share Text、Session 生命周期、PTY 输入、外部调用工具 Schema、输出脱敏或本地单用户边界。
- 不引入新的颜色自定义字段、主题导入导出、主题市场或第三方主题。
- 不把执行状态栏变成会阻止本地输入的模态层，也不在本变更中新增长期执行历史或审计记录。

## Decisions

### D1. 用 scheme 语义令牌替代散落的颜色覆盖

在现有主题调色板旁增加 UI 语义令牌，按职责分为三组：

- 内容：主要文字、辅助文字、弱化文字、禁用文字。
- 表面：卡片、控件、代码区域、悬停、选中、输入和弹层。
- 状态：信息、执行中、成功、警告、危险，以及各自的文字、背景、边框和强调色。

内置浅色和深色调色板分别提供完整值；组件 CSS 只引用令牌，不再用 `#93c5fd`、`#fecaca` 等只适合深色背景的直接颜色。品牌 Logo 和终端 ANSI 色板仍可保留独立颜色，因为它们不是桌面 UI 状态文字。

颜色辅助逻辑使用 WCAG 相对亮度计算：正常文字与背景至少 4.5:1，非文字控件边界和焦点指示至少 3:1。对比度测试针对令牌配对而不是截图像素，避免透明渐变或局部选择器覆盖造成回归。

备选方案是继续为每个组件增加 `[data-theme='light']` 覆盖。该方案会继续产生深色值遗漏和选择器优先级问题，因此不采用。

### D2. 将外部执行提示改成终端内容区的独立状态栏

外部执行提示保留为信息展示，不升级为审批卡片或模态交互。终端面板的结构调整为：

```text
prototype-terminal
├── external execution status bar  (有执行时占用固定布局空间)
└── terminal content layer
    ├── Terminal Session output
    └── terminal search control
```

状态栏采用单行优先的三段布局：左侧为执行中图标和状态，中间为等宽字体的命令摘要，右侧为来源标识。命令超出可用宽度时使用省略号，完整命令通过元素标题或等价的可访问详情保留；窄窗口允许状态栏内部换行，但不得覆盖终端内容或操作区。搜索控件放入 Terminal Session 内容层，避免与状态栏争夺同一顶部区域。

状态栏使用执行中语义令牌，不把“外部执行中”误表现为危险或错误。会话标签继续显示徽标，`started` 到 `finished` 的状态映射、wait 挂起期间持续显示和本地键盘输入路径保持不变。

备选方案是保留绝对定位并给终端增加动态顶部 padding。该方案依赖运行时测量，长文本、字体变化和窗口缩放下容易再次遮挡输出，因此不采用。

### D3. 保留审批卡片结构，重做层级和风险表达

审批卡片继续由现有 `McpApprovalRequest` 驱动，不增加 Main/preload 字段。视觉层级按“需要决定什么 → 影响哪个 Session → 执行什么命令 → 为什么需要决定 → 如何裁决”排列：

1. 标题区显示审批卡片标识和明确的人工裁决提示。
2. Session 与风险分类使用结构化信息行，风险分类使用 scheme 安全的状态标签和图标。
3. 命令全文位于独立代码区域，设置最大高度和内部滚动，长命令不会撑破视口。
4. 风险理由作为可读正文展示，不使用仅靠颜色的提示。
5. 底部操作区保留“允许一次”“本会话内放行该命令”“拒绝”，主操作、次操作和危险操作分别具有稳定的视觉层级；窄窗口按列堆叠。

卡片继续使用模态语义和现有窗口抢注意力行为，但不在 Renderer 增加超时计时逻辑，以免与 Main 的 60 秒事实源产生漂移。

### D4. 设置工作区采用相同令牌和清晰的密度层级

保留现有左侧设置分类导航和三个区块，不改变设置字段或 preload API。调整内容密度：标题和核心值使用主要文字，解释文字使用可读的辅助文字，状态提示使用状态令牌；关键说明不再依赖 9–10px 的低对比度文字。选中、聚焦、禁用和危险状态同时使用文字、边框、图标或明度差异表达。

MCP 服务区块中的连接串、请求头、Token、审批模式、完全权限警告和已共享 Session 列表统一使用控件/状态令牌。外观区块的颜色编辑器增加当前组合的可读性反馈，但不扩大为完整主题管理器。现有响应式策略继续保留，在窄窗口下将导航、卡片列和操作按钮堆叠，防止文字或按钮互相覆盖。

### D5. 自定义颜色采用“保存值保留、渲染安全回退”

合法的六位十六进制颜色仍由现有设置链路保存。主题解析额外评估背景/前景和强调色/控件文字组合：

- 组合满足阈值时，桌面 UI 使用用户的自定义值。
- 组合不满足阈值时，设置页显示明确警告，保存的合法值保持不变；受影响的桌面 UI 内容或控件改用当前 scheme 的安全回退颜色。
- 用户修正组合后，警告消失并恢复自定义值。

这样既不会因为先改背景还是先改前景造成编辑死锁，也不会把用户输入静默改写。终端 ANSI 自定义色仍按现有 `terminalText` 规则处理，其展示可读性由终端色板测试覆盖，不改变 PTY 或输出协议。

备选方案是直接拒绝所有低对比度颜色。该方案会让需要同时替换背景和前景的用户无法顺畅完成编辑，因此不采用。

### D6. 用行为测试和主题矩阵验收

Renderer 单测覆盖：

- 浅色/深色语义令牌的文字、背景、边框和焦点对比度。
- 审批卡片三个裁决动作、长命令代码区域和浅色主题文案。
- 执行状态栏的命令摘要、来源标识和完整命令可访问提示。
- 自定义低对比度组合的警告、安全回退和保存值保留。

Playwright 或等价视觉验收覆盖浅色/深色主题、执行状态出现/消失、超长命令、审批卡片、设置三个分类和窄窗口。执行期间额外验证终端仍可输入，审批流程和 Session 状态不因布局重构改变。

## Risks / Trade-offs

- [语义令牌迁移遗漏旧硬编码颜色] → 先建立令牌配对测试，再用 Renderer 样式搜索清理执行、审批、设置相关选择器，并以两种 scheme 截图复核。
- [状态栏改为流式布局影响 xterm 尺寸计算] → 状态栏显隐后触发已有 ResizeObserver/fit 路径，验证窗口 resize、切换 Session 和状态栏高度变化。
- [自定义主题安全回退造成用户误以为颜色未生效] → 在外观区块显示具体组合和可读性警告，明确区分“已保存颜色”和“当前安全回退”。
- [移动窄窗口下信息密度增加] → 保留命令摘要省略、代码区域滚动和按钮堆叠；将完整命令放在可访问标题/详情中。
- [颜色对比度测试与透明背景计算不一致] → 令牌测试优先使用不透明配对；透明渐变只作为装饰，不承载必要文字或状态含义。

## Migration Plan

本变更不需要数据迁移和 API 迁移。实现时先加入语义令牌与测试，再依次迁移执行状态栏、审批卡片和设置工作区；自定义主题设置文件格式保持兼容。若视觉回归失败，可回滚 Renderer 样式和布局提交，Main、preload、MCP 端点和终端服务不受影响。
