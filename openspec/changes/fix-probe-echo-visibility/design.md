## Context

参见 `proposal.md` 的 Why 和 What Changes。本地终端输出由 Main 侧的 SessionActor 接收并拆分为协议输出与本地终端 UI 输出；OSC 777 完成帧在进入两条输出路径前被隔离。命令完成 Probe 和环境识别 Probe 分别通过已注册的回显边界或 nonce 识别，当前识别状态会跨数据块保留，但回显边界只覆盖部分终端控制行为，且在完成帧排空后可能过早释放。

设计必须继续遵循 ADR-0016：`hideCompletionProbeEcho` 只改变本地终端 UI consumer，Probe 的固定明文写入、完成检测、协议输出、外部调用输出脱敏和 PTY 审计语义都不改变。Renderer 不直接接触 PTY 或 Session 内部状态，也不新增外部客户端工具契约。

## Goals / Non-Goals

**Goals:**

- 让自动 Probe 回显过滤成为跨 PTY 数据块的有状态处理，覆盖终端自动换行、重绘控制序列以及完成帧先于输入回显到达的情况。
- 只隐藏已确认属于当前自动 Probe 的回显，保留用户命令、普通输出、提示符和与 Probe 相邻的可读终端内容。
- 在回显尚未收完时切换设置，仍让后续本地终端 UI 输出服从最新设置；已经发送给 UI 的内容不做回溯改写。
- 通过终端服务单元测试、CommandExecutor 集成回归和设置应用测试固定上述边界。

**Non-Goals:**

- 不改变 Shell Driver 生成的 Probe 语法、nonce、用户命令字节序列、PTY 写入或 OSC 777 完成协议。
- 不把过滤移动到 Renderer，不实现完整的终端屏幕模拟，也不通过全局删除换行或控制字符来处理误匹配。
- 不隐藏用户主动输入的同名文本，不修改 `synapse_observe`、`synapse_execute` 或其他外部客户端工具的输入输出契约。
- 不新增设置迁移、Session 持久化、远程审计或 MCP 审批行为。

## Decisions

### 保留 Main 侧的双输出路径

过滤继续由持有 PTY 的 SessionActor 在 OSC 777 扫描之后完成。协议路径继续接收协议消费者所需的非 Probe 数据并隔离控制帧；本地终端 UI 路径根据 `hideCompletionProbeEcho` 决定是否使用已过滤的 Probe 数据。这样设置不会影响 PTY 写入或 CommandExecutor 的输出缓冲，也不需要扩大 preload API。

备选方案是让 Renderer 收到完整 PTY 输出后再隐藏文本，但这会把内部 Probe 和控制帧带过能力边界，并且无法保证其他 UI consumer 使用同一规则；让 PTY 不回显或改写 Probe 则会改变既有审计语义，因此不采用。

### 使用身份感知的流式匹配器

命令完成 Probe 使用 Shell Driver 提供的命令回显边界，环境识别 Probe 使用 nonce 和结果标记。两类匹配器都需要保存阶段、已确认的回显片段和跨数据块 carry，而不是对每个 PTY chunk 独立运行正则表达式。

匹配器只在一个已识别的 Probe 候选范围内，把终端回显可能插入的 ANSI/重绘控制序列、回车和自动换行分隔视为布局噪声；这些字符不会被全局从用户输出中删除。只有完整匹配到当前 Probe 身份和结束边界的片段才会从隐藏路径移除；候选与预期不符时，暂存的未确认文本必须恢复到普通输出，避免误吞用户内容。跨块的控制序列和标记前缀也必须进入 carry，直到能够安全判定。

备选方案是扩展一个“忽略所有控制字符和换行”的全局清理器，虽然实现简单，但会损坏用户的多行输出、重绘行为和提示符，且可能把普通文本拼成 Probe，因此不采用。

### 将完成后的释放改为有界的回显收尾状态

收到匹配的 OSC 777 完成帧不再立即删除命令完成 Probe 的过滤身份。过滤器先进入回显收尾状态，在现有 completion drain 之后继续保留一个有界的延迟回显收集窗口；如果完成帧先到，后续 PTY chunk 仍能匹配并隐藏对应的输入回显。只有预期回显已完整消费并遇到行边界，或收尾窗口到期，过滤身份才释放。

环境识别 Probe 在识别结果后采用同样的“等待已确认回显收尾再释放”原则。收尾状态必须有明确的超时、Session dispose 和新 Probe 替换路径，避免旧 nonce 无限累积；超时处理只释放已确认的 Probe 片段，未确认的普通文本按可见性设置正常交付。协议路径继续使用相同的身份隔离规则，不因本地 UI 开关改变。

备选方案是沿用完成帧后的立即释放，或无限期保留每个 nonce。前者无法覆盖延迟回显，后者会造成过期身份误匹配和状态增长，因此采用有界收尾状态。

### 将设置切换视为输出路由决策

事件处理时读取当前的隐藏值：隐藏时只向本地终端 UI 交付过滤后的数据，显示时交付原本会显示的终端数据，但两种模式都继续推进匹配器状态。切换不会重放历史事件，也不会改变协议事件、完成检测或已保存的事务输出。测试需要覆盖 Probe 回显进行中从隐藏到显示、从显示到隐藏的两种方向。

## Risks / Trade-offs

- [延迟超过收尾窗口] → 极端慢的 PTY 仍可能在窗口后发送回显；使用独立且长于常规 completion drain 的有界窗口，并以延迟回归测试校准，避免无限期拦截普通输出。
- [误匹配导致用户内容被隐藏] → 仅接受当前 Shell Driver/nonce 的完整身份和边界，候选失败时恢复未确认文本，并覆盖 Probe 前后夹带用户输出的测试。
- [控制序列处理改变普通终端表现] → 只在已确认候选内部进行匹配归一化，不修改交付给协议路径和显示路径的原始普通控制序列。
- [多个短生命周期 Probe 造成状态增长] → 每个 suppressor 都有完成、超时、替换和 dispose 清理路径，并限制 carry 与收尾状态的数量和大小。
- [动态切换产生前后不一致的视觉结果] → 明确切换只影响未来事件，不试图回溯已交付文本；协议输出和事务结果通过独立断言保持稳定。

## Migration Plan

不需要数据或协议迁移。现有 `hideCompletionProbeEcho` 持久化字段、默认值和设置文案继续兼容；实现上线后由 Main 在创建和更新 Session 时继续使用同一设置。回滚只需回退终端服务过滤实现和对应测试，已保存的设置文件无需转换。
