# ADR-0015：MCP 混合审批模型

状态：已接受

## 决策

外部调用审批采用混合模型：配置档位为主，高危升级人工。此决定部分推翻 develop ADR-0023 的"MCP 调用不依赖审批卡片"立场。

三档审批模式（配置缺失或损坏时回退 `read_only`）：

| 调用分类 | `read_only` | `managed` | `full` |
|---|---|---|---|
| 观察类 | 自动放行 | 自动放行 | 自动放行 |
| 低危写类 | 拒绝 | 自动放行 | 自动放行 |
| 高危（含特权、破坏性） | 拒绝 | 弹审批卡片 | 自动放行 |
| 未分类 | 拒绝 | 弹审批卡片 | 自动放行 |

审批卡片语义：

- **同步阻塞**：外部请求挂起等待人工裁决，固定 60 秒超时，超时即拒
- **稳定错误码区分**：`APPROVAL_TIMEOUT`（无人应答）与 `APPROVAL_DENIED`（主动拒绝）
- **按钮**：允许一次／会话内放行该命令（全文精确匹配、随会话消失、不落盘）／拒绝；无永久放行
- **形态**：应用内模态卡片 + 任务栏抢注意力，Main 持 FIFO 队列串行展示

`full` 模式必须由用户在设置页显式选择并带高风险提示；脱敏在三档模式下统一生效——`full` 放行的是执行权，不是明文输出权。

## 理由

develop 的纯配置门禁在真实 agent loop 中表现为莫名其妙的死拒，用户无解；纯人工审批则阻塞无人值守循环且本分支已无审批通道基础设施。混合模型把"人不在场"交给档位预决策，"人在场"交给卡片，并以超时默认拒绝守住活性底线。

## 影响

执行期间本地输入永不锁定（共享哲学）：标签徽标与面板条幅仅作信息展示，控制权始终留在本地终端。
