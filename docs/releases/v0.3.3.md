# Synapse Term v0.3.3

Synapse Term v0.3.3 是一次以 Agent Composer 为核心的桌面体验更新。本版本为 Composer 增加 Codex CLI 形态的 `/model`、`/permission`、`/clear` 快捷指令，支持在输入框上方选择命令与选项，并加入独立文件和图片附件入口。模型配置同步支持多模态能力声明，同时把“启用/停用”和“可用性检测结果”拆成独立列。

## 主要变化

### Agent Composer 快捷指令

- 新增 `/model`、`/permission`、`/clear` 三个系统指令，选择后直接更新当前 Session 的模型、权限模式或执行会话清空，不把斜杠命令作为普通文本发给 Agent。
- 斜杠命令候选列表在输入 `/` 后打开，支持过滤、`ArrowUp` / `ArrowDown` 选择、`Enter` 执行和 `Escape` 关闭。
- `/model` 与 `/permission` 打开 Composer 内选项面板后，继续支持 `ArrowUp` / `ArrowDown` 循环选择并用 `Enter` 确认。
- 命令面板和选项面板显示在输入框上方，避免遮挡正在编辑的内容；命令名称与描述间距保持清晰。
- Composer 记录当前 Session 的已发送提示词，支持 `ArrowUp` 回退上一条、`ArrowDown` 回到较新一条或导航前草稿。

### 文件与图片附件

- Composer 新增独立的“添加文件”和“添加图片”入口，附件会在输入区展示并支持移除。
- 文件附件作为本地任务附件引用，图片附件作为模型图片内容块进入首次用户消息。
- 未声明支持多模态的模型会禁用图片上传，并显示明确原因；普通文件附件不受该限制。
- Desktop Main 与 Core 对附件数量、大小、MIME 和多模态能力执行二次校验，避免只依赖 Renderer 界面限制。
- Timeline 会回显图片附件和文件附件元数据；对话重置后会清理本次任务附件上下文。

### 模型配置与多模态声明

- 模型配置增加手动“支持多模态”开关，新建和编辑模型时均可修改该声明。
- 模型列表把“启用/停用”和“可用性检测结果”拆为独立列，启用状态与检测状态不再合并为单一按钮。
- 修改多模态声明后，该模型检测状态会回到 `unverified`，避免沿用旧能力声明。

### Provider 与 Agent 运行链路

- `ModelCapabilities.multimodal` 进入模型配置、协议 View、Agent Model Selection 和 Provider Adapter 的同一能力表达。
- OpenAI Responses、OpenAI-compatible Chat Completions、Anthropic Messages 三种 Adapter 支持图片内容块转换。
- Core 在启动 Agent Turn 前执行附件校验和 staging，并把文件路径限制在当前 Session/Agent 附件根目录。
- 附件内容、多模态上传门槛、文件访问和 Timeline 回显同步写入 OpenSpec 主规格并完成变更归档。

## 安装与首次启动

### Windows

- Windows 发布资产为 x64 NSIS 安装包，文件名示例：`Terminal-Agent-0.3.3-x64-Setup.exe`。
- 当前版本尚未配置 Windows 产品签名证书，首次安装可能触发 SmartScreen 提示。

### macOS

- 本版本发布资产为 arm64 DMG，适用于 Apple Silicon Mac。
- 下载 DMG 和 `SHA256SUMS.txt`，确认安装包校验值匹配。
- 打开 DMG，将 Synapse Term 拖入“应用程序”文件夹。
- 在“应用程序”中右键点击 Synapse Term，选择“打开”，并确认启动。
- 本版本尚未配置 Apple Developer ID 签名和公证。如果 macOS 显示“Synapse Term 已损坏，无法打开”，且你确认 DMG 来自本 Release 并且校验值匹配，可以在终端执行：

  ```bash
  xattr -dr com.apple.quarantine "/Applications/Synapse Term.app"
  open -a "/Applications/Synapse Term"
  ```

  上述命令只移除该应用的下载隔离属性；不要对来源不明的应用执行。
- 检查当前 Mac 架构可以运行：

  ```bash
  uname -m
  ```

  显示 `arm64` 才能使用当前 macOS 安装包。

## 验证与下载

发布工作流会在创建 Release 前运行仓库验证，并在 Windows 和 macOS runner 上分别构建安装包、运行 Core/维护入口 smoke、生成 `SHA256SUMS.txt` 后创建正式 Release。下载后可先核对校验文件，再执行安装或手动启动验证。

## 已知限制

- 未签名安装包在 Windows 和 macOS 上均可能显示系统安全提示。
- 当前 GitHub Release 提供 Windows x64 和 macOS arm64 构建，不包含 Windows arm64、macOS Intel 或 Linux 安装包。
- 真实 Provider、模型凭据、SSH 和远程环境验收依赖用户自己的环境，不属于默认发布门槛。
- `codex`、`opencode` 等外部 CLI 不随安装包发布，ACP 使用的外部运行时需要用户单独安装。
