# Synapse Term v0.3.0

Synapse Term v0.3.0 是一次面向本地终端、Agent 协作和外部 Agent 接入的架构升级版本。本版本将桌面端、Core 运行时、终端会话、模型 Provider、MCP 和 ACP 集成整理为可验证的本地优先工作流，并同步更新项目文档与发布流水线。

## 主要变化

### 架构与运行时

- 将 Core 进程作为本地终端会话和 Agent 运行时的主要归属边界。
- 将业务能力拆分为 workspace packages，并由 `apps/core` 和 Electron Desktop 负责装配。
- 让终端 Session 与具体传输方式解耦，支持会话创建、复用、关闭、恢复和生命周期审计。
- 保留分层输出留存、会话资源快照、上下文压缩和 Core 重启边界，降低长时间运行任务的状态风险。
- 将 Agent 状态机、Turn、工具调用、审批和审计统一到现有会话模型中。

### Provider、Model 与 Agent

- 统一 Provider 配置、Model 配置、模型发现、连通性检测和默认模型选择流程。
- 支持多种模型协议通过统一内部适配层接入，避免 UI 和 Core 直接依赖单一 SDK。
- 增加 ACP 外部 Agent 子进程驱动，当前以 OpenCode 作为首个内置驱动实现。
- 将 ACP 的能力声明、终端控制、只读文件访问、Turn 生命周期和权限请求映射到 Synapse Term 的既有模型。
- 保持一段会话与一个长期 Agent 进程的关联，减少上下文和权限状态错配。

### MCP 与外部调用

- 在桌面应用内嵌 MCP Server，并通过 Session ID 将外部调用绑定到明确的本地会话。
- 将外部命令建模为可审计的 Command Transaction，保留调用者身份、风险、审批和执行结果。
- 对 MCP 和 ACP 的权限请求使用统一审批通道，并默认拒绝未配置的高风险能力。
- 保持 Codex 作为 MCP Client 的集成边界，避免把外部调用方直接耦合到 Core 内部实现。

### 安全与权限

- 未知命令默认需要审批，审批绑定到精确命令而不是模糊的会话状态。
- 交互式程序需要用户接管，Agent 不会静默夺取当前终端控制权。
- 在模型披露、审计记录和外部调用边界前保护敏感信息。
- `manual`、`managed`、`full_access` 等权限模式只改变审批策略，不扩大工具的资源边界。
- 发布说明、构建产物和验证流程明确排除 Provider 凭据、SSH 配置、远端主机信息、用户数据库和测试 token。

### 桌面端体验

- 使用运行时 Session、Resource、Agent、Approval 和 Audit 数据驱动桌面工作区。
- 支持多 Session 标签、搜索、会话复用、终端输出查看、Agent Timeline、审批卡片和运行时错误处理。
- 支持 Agent 面板布局调整、隐藏与恢复，以及在紧凑桌面尺寸下保持主要工作流可见。
- 统一产品主名称为 `Synapse Term`；部分旧 UI 文案、环境变量、数据目录和安装文件名仍保留 `terminal-agent` 兼容标识。

### 文档与发布工程

- 根据当前代码重写 README 和 `docs/` 下的架构、配置、安全、运行手册、发布报告、验证矩阵及 ADR 文档。
- 保留 GitHub Actions 的持续集成和 Release 流程：验证、Windows x64、macOS arm64、Core smoke、维护入口 smoke、SHA256 校验和自动 Release。
- Release 资产使用 `v*` 标签触发，普通 `main` 分支推送不会直接创建 Release。

## 兼容性与发布资产

- Windows：x64 NSIS 安装包。
- macOS：arm64 DMG，使用 GitHub Actions 的 `macos-14` runner 构建。
- 安装包文件名仍以 `Terminal-Agent-` 开头，这是兼容性命名；构建产品名为 `Synapse Term`。
- 当前未配置 Windows 或 macOS 产品签名证书，系统可能显示未签名应用的安全提示。
- Release 包含对应平台安装文件和 `SHA256SUMS.txt` 校验文件。
- 外部 ACP 运行时（例如 OpenCode）不随安装包发布，需要由用户单独安装和配置。

## 验证结果

本地发布前验证结果：

- `pnpm verify`：138 个测试文件通过，3 个跳过；648 个测试通过，12 个跳过。
- `pnpm test:e2e`：27 个通过，4 个跳过。
- `pnpm build`：成功完成 Desktop 和 Core 构建。
- Prettier、Lint、TypeScript 类型检查和 `git diff --check`：通过。

GitHub Actions 会在 Release 发布前使用干净 runner 重新执行验证，并在 Windows 和 macOS runner 上重新生成发布资产。

## 已知限制

- 未签名安装包可能触发操作系统安全警告。
- Windows、macOS 打包和原生模块构建依赖对应 GitHub-hosted runner 环境。
- 真实 Provider、模型凭据、SSH 和远程环境验收不属于默认 CI 门槛。
- 旧 `terminal-agent` 环境变量和数据迁移路径仍需保留；完全删除兼容标识需要单独的迁移版本。
