# 领域文档

说明各工程类 skill 在探索代码库时应如何消费本仓库的领域文档。

本仓库为**单上下文（single-context）**布局。

## 探索之前，先读这些

- **`CONTEXT.md`**（仓库根目录）：领域统一语言。
- **`docs/adr/`**：先读与你即将改动的领域相关的 ADR。

若这些文件不存在，**静默继续**。不要指出其缺失，也不要主动建议创建。`/domain-modeling` skill（经由 `/grill-with-docs` 与 `/improve-codebase-architecture` 触达）会在术语或决策真正被确定时按需创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── packages/
```

## 使用术语表词汇

当你的输出涉及某个领域概念（issue 标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 中定义的词条，不要漂移到术语表明确回避的近义词。

如果你需要的概念尚未进入术语表，这是一个信号：要么你在发明项目并不使用的语言（重新考虑），要么这里存在真实的缺口（记为待 `/domain-modeling` 处理）。

## 标记 ADR 冲突

若你的输出与既有 ADR 相矛盾，明确地提出来，而不是静默覆盖：

> _与 ADR-0007（…）相矛盾，但因……值得重新讨论。_
